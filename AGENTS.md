# AGENTS.md — places

Expo 57 + React 19 + React Native 0.86 + TypeScript strict + NativeWind (Tailwind 3.4).
Entry: `expo-router/entry` with routes in `src/app/`. Scheme: `go2s`. Greenfield, no backend/auth yet.

## Setup & run (bun only)

- Install: `bun install`
- Dev server: `bun run start` — clear cache after Metro/Babel/Tailwind changes: `bunx expo start --clear`
- Platform: `bun run ios` | `bun run android` | `bun run web`
- Doctor / versions: `bunx expo-doctor`; add native deps with `bunx expo install <pkg>`, never plain `bun add`
- Typecheck: `bunx tsc --noEmit`
- Lint: `bun run lint`
- Format: `bun run format`
- Test: `bun run test` (Jest + jest-expo, never `bun test`) | watch: `bun run test:watch`
- Git hooks (husky, installed by `prepare`): pre-commit runs lint-staged on staged files;
  pre-push runs tsc and tests. Do not bypass with `--no-verify` unless the user asks; if a hook
  fails, fix the cause.

Test runner: Jest via `bun run test`. Stack: `jest-expo` preset, React Native Testing Library
v14 + `test-renderer@1.2` (matches React 19.2, requires Node >=22.13). Tests live in
`__tests__/` (or per-area `__tests__/` subdirs) as `*-test.{ts,tsx}` per Expo docs
(e.g. `__tests__/ScreenContent-test.tsx`); always `await render(...)` + `screen.*` queries.
Assert text/behaviour with RNTL queries (`getByText`, `toBeOnTheScreen()`); do not assert
NativeWind styles in Jest (v4 compiles `className` via the Metro pipeline, invisible to
plain Jest — style coverage is intentionally out of scope).
Config: `jest.config.js`, `jest-setup.js`.

## Layout

- `src/app/`: file-based routes (Expo Router). `_layout.tsx` is root composition only
  (`SafeAreaProvider`, `global.css`, `Stack`). `index.tsx` is `/`. New page = new file
  (e.g. `src/app/search.tsx` → `/search`). No web support (iOS/Android only).
- `src/components/`: shared presentational components (`ScreenContent.tsx`, `EditScreenInfo.tsx` pattern).
- `__tests__/`: Jest tests as `*-test.{ts,tsx}` mirroring `src/` (e.g. `__tests__/ScreenContent-test.tsx`).
- `assets/`: icons, splash, favicon. Referenced from `app.json`.
- `app.json`, `babel.config.js`, `metro.config.js`, `tailwind.config.js`, `global.css`: styling/native chain — change together.
- `tsconfig.json`: `strict:true`, `baseUrl:"."`, alias `@/* -> ./src/*`.
- `.husky/`: git hooks (pre-commit, pre-push). Config for lint-staged lives in `package.json`.
- `.github/`: issue forms (`ISSUE_TEMPLATE/`), PR template, CI workflow. Change the forms and the
  PR template together with the workflow steps they reference.

## Code style

- TypeScript strict. Type props with `interface XProps`. No `any` except to unblock with `// TODO:`.
- Functional components + named exports only, except `src/app/` route files which require
  `export default` per Expo Router convention. No class components.
- Styling with NativeWind `className` by default. Never `StyleSheet.create` or CSS modules.
  Inline `style={}` is allowed only with a why-comment, and only when one holds:
  - the third-party / native component's docs explicitly recommend `style`
    (e.g. `GestureHandlerRootView style={{ flex: 1 }}`), or
  - a platform API value (e.g. Animated/Reanimated) cannot be expressed as classes, or
  - `className` is proven broken on device and `style` fixes it — never assume,
    verify on simulator/device first.

```tsx
export const Foo: React.FC<FooProps> = ({ title }) => (
  <View className="flex-1 items-center justify-center bg-white">
    <Text className="text-xl font-bold">{title}</Text>
  </View>
);
```

- Prettier: `singleQuote, printWidth:100, bracketSameLine:true, trailingComma:es5`. Tailwind classes sorted by `prettier-plugin-tailwindcss` — do not hand-sort.
- Avoid comments unless absolutely necessary — e.g. to explain why a specific approach was
  chosen over an intuitive alternative. Never narrate what the code does.
- Keep `global.css` imported in `src/app/_layout.tsx`. Keep `withNativeWind(..., {input:'./global.css'})` in `metro.config.js`.
- `tailwind.config.js`: `preset: nativewind/preset` and `content` covering every `*.{js,ts,tsx}` dir with `className`.

## Never do

- Do not introduce `StyleSheet.create` or CSS modules. Inline `style={}` only for the
  documented cases in Code style (third-party docs, platform APIs, device-proven
  breakage), each with a why-comment. Default to `className`.
- Do not hand-edit `ios/` / `android/` (generated by `expo prebuild`, gitignored). Use config plugins in `app.json`.
- Do not remove `react-native-worklets/plugin` from `babel.config.js` or change preset order.
- Do not use `npm`/`yarn`/`pnpm` commands. This repo uses `bun`.
- Do not commit `node_modules/`, `.expo/`, `dist/`, `web-build/`.
- Do not add auth/secrets handling without updating this file with storage + review rules.
- Do not commit to `main`, push, or create pull requests without the user's approval. Commits
  on a task branch are allowed under Issue-driven work.
- Never edit a file from memory — always `Read` it first in the current session and derive
  edits from the read result, unless the user explicitly says otherwise.

## Verification before done

1. `bunx tsc --noEmit` clean.
2. `bun run lint` clean.
3. `bun run test` — all tests pass before submitting a PR.
4. `bunx expo start --clear` boots without Metro errors, or `bun run web` builds.
5. After adding/changing native dependencies: clean rebuild and boot on
   simulator/device (`bunx expo prebuild --clean` when `ios/`/`android/` look stale,
   then `bun run ios`) and exercise the changed surface. Jest mocks native modules
   and a Metro boot alone prove nothing here.
6. Keep diff minimal; update this file if you change commands, layout, or styling chain.

## Issue-driven work

When given a GitHub issue (URL or number):

1. Read the issue with `gh-axi issue` (or `gh issue view`). If Acceptance Criteria or
   Affected Area is missing or unclear, ask before coding.
2. Work in a git worktree, never by switching branches in the user's checkout. It may hold
   unrelated uncommitted work. Use a sibling directory so tsc, Jest and Metro never see nested
   copies:
   `git worktree add -b <type>/<issue#>-<slug> ../places-worktrees/<issue#>-<slug> main`
   then `bun install --frozen-lockfile` inside it. Branch `<type>` is a Conventional Commit type.
3. Implement only the issue's Acceptance Criteria. Respect Out of Scope. Keep the smallest diff.
4. Commit atomically: one logical change per commit, Conventional Commits. Each commit
   passes `bunx tsc --noEmit` and `bun run lint`. Run `bun run test` before the final report.
5. Native change in the issue: boot on simulator and exercise the feature before reporting done.
6. Stop before the PR. Report: branch, commit list, verification output, and open questions.
   Then wait for feedback. Do not push or open the PR until the user approves.
7. On approval: push the branch, then `gh pr create --draft` with the body from
   `.github/PULL_REQUEST_TEMPLATE.md`, title as a Conventional Commit, `Closes #<issue>`. Never merge.

## Commit etiquette

Use [Conventional Commits](https://www.conventionalcommits.org/) for every commit.
AI-generated commits follow the same rules. No exceptions.

Format: `<type>(<scope>): <subject>` + optional body. Scope is optional — omit it when no specific area applies.

Types: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `revert`.
Scopes: area touched, e.g. `auth`, `expo`, `deps`, `ci`, `docs`.
Subject: imperative mood, lowercase, no trailing period, max ~72 chars.
Body: explain why, not what. Wrap at ~100 chars.

Examples:

- `feat: add favorites filter`
- `fix(auth): refresh expired session token`
- `chore(expo): upgrade SDK 56 to 57`
- `chore(deps): bump reanimated to 4.5.1`
- `docs: clarify iOS simulator setup`
