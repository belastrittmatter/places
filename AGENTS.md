# AGENTS.md — places

Expo 57 + React 19 + React Native 0.86 + TypeScript strict + NativeWind (Tailwind 3.4).
Entry: `App.tsx` (via `node_modules/expo/AppEntry.js`). Greenfield, no backend/auth yet.

## Setup & run (bun only)

- Install: `bun install`
- Dev server: `bun run start` — clear cache after Metro/Babel/Tailwind changes: `bunx expo start --clear`
- Platform: `bun run ios` | `bun run android` | `bun run web`
- Doctor / versions: `bunx expo-doctor`; add native deps with `bunx expo install <pkg>`, never plain `bun add`
- Typecheck: `bunx tsc --noEmit`
- Lint: `bun run lint`
- Format: `bun run format`
- Test: `bun run test` (Jest + jest-expo, never `bun test`) | watch: `bun run test:watch`

Test runner: Jest via `bun run test`. Stack: `jest-expo` preset, React Native Testing Library
v14 + `test-renderer@1.2` (matches React 19.2, requires Node >=22.13). Tests live in
`__tests__/` (or per-area `__tests__/` subdirs) as `*-test.{ts,tsx}` per Expo docs
(e.g. `__tests__/ScreenContent-test.tsx`); always `await render(...)` + `screen.*` queries.
Assert text/behaviour with RNTL queries (`getByText`, `toBeOnTheScreen()`); do not assert
NativeWind styles in Jest (v4 compiles `className` via the Metro pipeline, invisible to
plain Jest — style coverage is intentionally out of scope).
Config: `jest.config.js`, `jest-setup.js`.

## Layout

- `App.tsx`: root composition only (`SafeAreaProvider`, `global.css`, screen). No business logic.
- `src/components/`: shared presentational components (`ScreenContent.tsx`, `EditScreenInfo.tsx` pattern).
- `__tests__/`: Jest tests as `*-test.{ts,tsx}` mirroring `src/` (e.g. `__tests__/ScreenContent-test.tsx`).
- `assets/`: icons, splash, favicon. Referenced from `app.json`.
- `app.json`, `babel.config.js`, `metro.config.js`, `tailwind.config.js`, `global.css`: styling/native chain — change together.
- `tsconfig.json`: `strict:true`, `baseUrl:"."`, alias `@/* -> ./src/*`.

If introducing Expo Router, extend `tailwind.config.js content` and document here.

## Code style

- TypeScript strict. Type props with `interface XProps`. No `any` except to unblock with `// TODO:`.
- Functional components + named exports only. No default component exports, no class components.
- Styling with NativeWind only. Inline `className` strings, never `StyleSheet.create`, `style={}`, or CSS modules — except when a platform API (e.g. Animated/Reanimated values) cannot be expressed as classes:

```tsx
export const Foo: React.FC<FooProps> = ({ title }) => (
  <View className="flex-1 items-center justify-center bg-white">
    <Text className="text-xl font-bold">{title}</Text>
  </View>
);
```

- Prettier: `singleQuote, printWidth:100, bracketSameLine:true, trailingComma:es5`. Tailwind classes sorted by `prettier-plugin-tailwindcss` — do not hand-sort.
- Avoid comments unless absolutely necessary — e.g. to explain why a specific approach was
  chosen over an intuitive alternative. Never narrate what the code does.
- Keep `global.css` imported in `App.tsx`. Keep `withNativeWind(..., {input:'./global.css'})` in `metro.config.js`.
- `tailwind.config.js`: `preset: nativewind/preset` and `content` covering every `*.{js,ts,tsx}` dir with `className`.

## Never do

- Do not introduce `StyleSheet.create`, inline `style={}`, or CSS modules. Use NativeWind `className`. Exception only for Animated/Reanimated values that can't be expressed as classes — justify in PR.
- Do not hand-edit `ios/` / `android/` (generated by `expo prebuild`, gitignored). Use config plugins in `app.json`.
- Do not remove `react-native-worklets/plugin` from `babel.config.js` or change preset order.
- Do not use `npm`/`yarn`/`pnpm` commands. This repo uses `bun`.
- Do not commit `node_modules/`, `.expo/`, `dist/`, `web-build/`.
- Do not add auth/secrets handling without updating this file with storage + review rules.
- Do not commit files / create pull requests before explicitly being told to do so.
- Never edit a file from memory — always `Read` it first in the current session and derive
  edits from the read result, unless the user explicitly says otherwise.

## Verification before done

1. `bunx tsc --noEmit` clean.
2. `bun run lint` clean.
3. `bun run test` — all tests pass before submitting a PR.
4. `bunx expo start --clear` boots without Metro errors, or `bun run web` builds.
5. Keep diff minimal; update this file if you change commands, layout, or styling chain.

## Commit etiquette

Use [Conventional Commits](https://www.conventionalcommits.org/) for every commit.
AI-generated commits follow the same rules. No exceptions.

Format: `<type>(<scope>): <subject>` + optional body. Scope is optional — omit it when no specific area applies.

Types: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `revert`.
Scopes: area touched, e.g. `auth`, `expo`, `deps`, `ci`, `docs`.
Subject: imperative mood, lowercase, no trailing period, max ~72 chars.
Body: explain why, not what. Wrap at ~100 chars.

Examples:

- `feat: add favorites filter`
- `fix(auth): refresh expired session token`
- `chore(expo): upgrade SDK 56 to 57`
- `chore(deps): bump reanimated to 4.5.1`
- `docs: clarify iOS simulator setup`
